# Daily Quest #18 — Train troops in the Barracks

## Goal

Complete the Daily Quest target by training **800 troops**.

The confirmed implementation uses Tier-1 Grunt because Tier 1 is always present
in the Barracks UI and the supplied account has Grunt available.

## Confirmed Barracks flow

1. Start from Castle.
2. Search the Castle area for a Barracks.
3. Pan and rescan within a bounded number of search steps.
4. Open Barracks.
5. Select the Tier-1 Grunt card.
6. Tap the quantity field.
7. Confirm that the numeric keypad is open.
8. Enter exactly 800 using the keypad.
9. Confirm the quantity.
10. Detect the Train button.
11. If resources are sufficient, tap Train.
12. If the game shows the resource-shortage dialog, tap its Use button.
13. The confirmed behavior is that Use automatically supplies the required
    resources and presses Train for us.
14. Detect Finish Now and tap it to speed up the training.
15. Verify the training state after Finish Now.

## Tier / troop selection

The Barracks screen can contain five troop columns per tier and multiple
tiers. The account may have different unlocked tiers.

The routine does not need to scroll through every troop type for Quest #18.
It uses the always-present Tier-1 Grunt as the production target.

This also gives Quest #4 a future reusable path:

Shelter has no troops
→ open Barracks
→ select Grunt
→ request a small validated quantity
→ Train / resource Use
→ return to Shelter.

The one-Grunt path must be parameterized from the same training state machine;
it must not duplicate Barracks logic.

## Quantity entry

The supplied LDPlayer screenshots confirm a numeric keypad after tapping the
quantity field.

The confirmed sequence for Quest #18 is:

8 → 0 → 0 → confirm

The keypad is visually confirmed before the digit taps are performed.

No ADB text injection is required.

## Resource shortage

The supplied shortage screenshot confirms a dialog titled:

Use to meet project requirements

It lists resource items under Auto Use and exposes a Use button.

The confirmed behavior is:

Train
→ shortage dialog
→ Use
→ game automatically supplies the missing resources
→ game automatically presses Train
→ Finish Now / Speed Up

Therefore the routine must NOT independently press Train after Use.

It re-scans the shortage state after Use and continues to Finish Now only when
the shortage has disappeared.

No manual resource-item selection is needed for this confirmed flow.

## Speed Up

The confirmed training screen exposes Finish Now.

Quest #18 will use Finish Now to complete the queued 800 troop training rather
than waiting for the displayed timer.

The exact post-speed-up verification will be validated live.

## Castle search

Barracks may be outside the current viewport.

Use:

scan → pan → scan → ... → bounded failure.

No fixed Barracks coordinate is accepted as the final implementation.

The pan gestures are provisional and must be tuned from live LDPlayer behavior.

## Safety

- Missing templates fail before interaction.
- Castle search is bounded.
- Numeric keypad is detected before digit input.
- The routine does not press Train after resource Use because the game does
  that automatically.
- Finish Now is detected before speed-up.
- No fixed resource-option coordinates are used.
- Global PopupManager remains responsible for global popups.
- Routine does not call ADB directly.
