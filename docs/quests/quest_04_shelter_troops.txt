# Daily Quest #4 — Shelter troops

## Goal

Complete the Daily Quest by sheltering troops once.

The target is 1 successful Shelter action.

## Confirmed LDPlayer flow

1. Start from the Castle.
2. Search the Castle area for the Shelter building.
3. The Shelter is not assumed to be at one fixed coordinate. The Castle
   viewport is panned and rescanned with a bounded search.
4. Detect and tap the Shelter building.
5. The game opens the Shelter duration dialog.
6. The current account defaults to 1 hour. Use the currently selected/default
   duration; duration selection is not part of the Daily Quest target.
7. Detect and tap the duration dialog OK button.
8. The troop-selection screen opens.
9. Detect the account-independent empty-troop state.
10. If the empty state is present, call the reusable troop-training hook.
11. Re-check the empty state after training.
12. If troops are available, detect and tap Shelter.
13. Verify the Shelter action is no longer present.

## Critical troop availability rule

Troop types and counts differ between accounts.

The routine MUST NOT identify every troop type or require a specific troop
template.

The account-independent negative state is:

"You need to train more Troops at the Barracks."

Decision:

- no_troops.png FOUND → NO TROOPS → request reusable training recovery.
- Training hook unavailable/fails → abort safely.
- Re-check no_troops.png after training.
- no_troops.png still FOUND → abort safely.
- no_troops.png NOT FOUND → continue to detect Shelter.
- Shelter action missing → fail safely.
- Never press Shelter while no_troops.png is detected.

## Reusable Train Troops integration

The zero-troop recovery belongs conceptually to Daily Quest #18
"Train troops in the Barracks".

Quest #4 therefore exposes an optional ensure_troop_available hook instead of
duplicating Barracks logic.

The intended future flow is:

Shelter → zero troops
→ Quest #18 reusable Barracks flow
→ train at least 1 Grunt
→ return to Shelter flow
→ re-check no_troops.png
→ Shelter

The exact Barracks navigation and Grunt training templates must be established
from real LDPlayer screenshots before implementing Quest #18.

## Castle search strategy

The Shelter building can be outside the current viewport.

The routine:

1. scans the current viewport;
2. pans the Castle area;
3. rescans;
4. repeats only within a bounded number of search steps;
5. fails safely if Shelter is not found.

The current pan path is provisional and must be tuned only from live LDPlayer
evidence if the game camera behaves differently.

No Shelter target coordinate is hardcoded.

## Verification

Success requires:

- Shelter building detected;
- Shelter building tap succeeds;
- duration OK detected and tapped;
- troop-selection screen reached;
- no_troops.png is NOT detected after any required training recovery;
- Shelter action detected;
- Shelter action tap succeeds;
- Shelter action is no longer detected after the action.

Failure includes:

- Shelter not found after bounded Castle search;
- any required template missing;
- any navigation/action tap failure;
- explicit no-troops state with failed/unavailable training recovery;
- Shelter action not found;
- Shelter action remains visible after the tap.

## Safety

- Missing templates fail before any game interaction.
- Explicit no-troops state is a hard safety gate.
- The routine never selects a troop type by name or assumes a troop count.
- Global popup handling remains owned by AutomationEngine / PopupManager.
- The routine does not talk directly to ADB.
- Training recovery must succeed before Shelter is attempted again.

## Architecture

AutomationEngine
→ Global Popup Safety
→ QuestManager
→ ShelterTroopsRoutine
→ optional TrainTroops recovery
→ ActionEngine
→ Detector / Vision
→ ADB
