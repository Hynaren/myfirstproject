# Daily Quest #4 — Shelter troops

## Goal

Complete the Daily Quest by sheltering troops once.

The target is 1 successful Shelter action.

## Confirmed LDPlayer flow

The supplied real screenshots establish this flow:

1. Start from the Castle.
2. Search the Castle area for the Shelter building.
3. The Shelter is not assumed to be at one fixed coordinate. The Castle
   viewport is panned and rescanned with a bounded search.
4. Detect and tap the Shelter building.
5. The game opens the Shelter duration dialog.
6. The current account defaults to 1 hour. The routine may use the
   currently selected/default duration; duration selection is not part of
   the Daily Quest target.
7. Confirm the dialog with OK.
8. The troop-selection screen opens.
9. Determine whether troops are available.
10. If the game displays the stable empty state
    "You need to train more Troops at the Barracks.", stop safely and do
    NOT press Shelter.
11. If that empty state is absent, detect the Shelter action and tap it.
12. Verify the active Shelter action is no longer present.

## Critical troop availability rule

Troop types and counts differ between accounts.

Therefore the routine MUST NOT try to identify every troop type or require a
specific troop template.

The account-independent negative state is:

> You need to train more Troops at the Barracks.

This state means there are zero eligible troops for the Shelter action.

Decision:

- no_troops.png FOUND → NO TROOPS → abort safely
- no_troops.png NOT FOUND → continue to detect the Shelter action
- Shelter action missing → fail safely
- Never press the Shelter button while no_troops.png is detected.

This is intentionally a negative-state strategy because it works across
accounts with different troop compositions.

All production templates must come from real LDPlayer screenshots.

Do not use:
- fixed Shelter coordinates;
- troop-type-specific templates;
- OCR;
- web screenshots;
- invented UI states.

## Castle search strategy

The Shelter building can be outside the current viewport.

The routine:

1. scans the current viewport;
2. pans the Castle area;
3. rescans;
4. repeats only within a bounded number of search steps;
5. fails safely if Shelter is not found.

The current pan path is provisional and must be tuned only from live LDPlayer
evidence if the game camera behaves differently.

No Shelter target coordinate is hardcoded.

## Verification

Success requires:

- Shelter building detected;
- Shelter building tap succeeds;
- troop-selection screen reached;
- no_troops.png is NOT detected;
- Shelter action detected;
- Shelter action tap succeeds;
- Shelter action is no longer detected after the action.

Failure includes:

- Shelter not found after bounded Castle search;
- any required template missing;
- any navigation/action tap failure;
- explicit no-troops state detected;
- Shelter action not found;
- Shelter action remains visible after the tap.

## Safety

- Missing templates fail before any game interaction.
- Explicit no-troops state is a hard stop.
- The routine never selects a troop type by name or assumes a troop count.
- Global popup handling remains owned by AutomationEngine / PopupManager.
- The routine does not talk directly to ADB.

## Architecture

AutomationEngine
→ Global Popup Safety
→ QuestManager
→ ShelterTroopsRoutine
→ ActionEngine
→ Detector / Vision
→ ADB
